Léelo en orden la primera vez. Cada capítulo termina con una breve lista de comprobación a la que puedes volver más adelante.

## La versión corta

1. Elige un proyecto que utilices o que te interese, que haya aceptado pull requests de colaboradores externos durante el último mes.
2. Elige un issue etiquetado para principiantes que nadie tenga asignado y que no tenga ningún pull request asociado.
3. Lee la guía de contribución. Síguela exactamente.
4. Reproduce el problema antes de cambiar nada.
5. Haz el cambio más pequeño que solucione el problema, acompañado de una prueba.
6. Ejecuta localmente las pruebas, el formateador y el linter propios del proyecto.
7. Abre un pull request que explique qué estaba mal, qué cambiaste y cómo lo comprobaste.
8. Responde a las revisiones de forma educada y rápida. Repite.
