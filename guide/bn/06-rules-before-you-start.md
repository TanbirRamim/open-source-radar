# ৬. শুরু করার আগে যে নিয়মগুলো যাচাই করবেন

প্রতিটি প্রজেক্টে contribution করার জন্য কিছু নির্দিষ্ট নিয়ম থাকে। কিছু নিয়ম শুধুই প্রচলিত রীতি, আবার কিছু নিয়ম নির্ধারণ করে আপনার Pull Request merge করা যাবে কি না, এমনকি সেটি স্বয়ংক্রিয়ভাবে বন্ধ হয়ে যাবে কি না। তাই code লেখার আগেই এই নিয়মগুলো **ভালোভাবে দেখে নিন**।

[Issue index](../../issues/README.md)-এ প্রতিটি প্রজেক্টের জন্য স্বয়ংক্রিয়ভাবে শনাক্ত করা কিছু নির্দেশনা দেখানো হয়। তবে এগুলো কেবল প্রাথমিক ধারণা, নিশ্চিত তথ্য নয়। তাই সবসময় প্রজেক্টের নিজস্ব ফাইলগুলো পড়ে নেবেন।

| Index-এ দেওয়া নোট | এর অর্থ |
| --- | --- |
| ⚠️ AI restricted | প্রজেক্টের contribution সংক্রান্ত ফাইলগুলোতে AI দিয়ে তৈরি contribution নিষিদ্ধ করা হয়েছে অথবা এর ব্যবহারে কঠোর সীমাবদ্ধতা রয়েছে |
| 🤖 disclose AI use | প্রজেক্টে AI-এর সাহায্য নিলে তা প্রকাশ করতে বলা হয়েছে |
| 📄 AI policy | প্রজেক্টে AI ব্যবহারের নির্দিষ্ট নীতিমালা রয়েছে; সেটি পড়ে নিন |
| ✍️ CLA | সম্ভবত আপনাকে Contributor License Agreement-এ স্বাক্ষর করতে হবে |
| 🔏 DCO | সম্ভবত প্রতিটি commit-এ `Signed-off-by` লাইন যোগ করতে হবে |

## নিয়মগুলো কোথায় পাবেন

শুধু README নয়, নিচের সব জায়গায় নিয়মগুলো খুঁজে দেখুন:

- `CONTRIBUTING.md` (root, `.github/`, অথবা `docs/`-এর মধ্যে)
- `.github/PULL_REQUEST_TEMPLATE.md` এবং issue templates
- `CODE_OF_CONDUCT.md`
- `AI_POLICY.md`, `AGENTS.md`, `.github/copilot-instructions.md`, `.github/instructions/`, `.claude/`, `.cursor/rules`
- `DEVELOPMENT.md`, `docs/development/`, অথবা প্রজেক্টের ওয়েবসাইটে থাকা contributing page
- `.github/workflows/` (Pull Request-এ label যোগ করা, পরীক্ষা চালানো বা সেগুলো বন্ধ করার automation)

## Contributor License Agreement (CLA)

CLA হলো একটি আইনি চুক্তি, যার মাধ্যমে আপনি প্রজেক্টকে (অথবা এর পেছনে থাকা কোম্পানিকে) আপনার contribution ব্যবহারের অধিকার দেন। অনেক কোম্পানি-সমর্থিত প্রজেক্টে এই চুক্তিতে স্বাক্ষর করা বাধ্যতামূলক।

- সাধারণত আপনার প্রথম Pull Request-এর পর একটি bot মন্তব্যের মাধ্যমে স্বাক্ষর করার link দেয়। আপনি একবার অনলাইনে স্বাক্ষর করলেই সেটি ওই প্রজেক্ট বা organization-এ আপনার পরবর্তী contribution-এর ক্ষেত্রেও প্রযোজ্য হয়।
- কিছু CLA organization-ভিত্তিক account-এর সঙ্গে যুক্ত থাকে। যেমন Linux Foundation-এর EasyCLA (যা অনেক CNCF প্রজেক্টে ব্যবহৃত হয়) অথবা Google-এর CLA।
- **কী স্বাক্ষর করছেন, তা ভালোভাবে পড়ে নিন।** আপনি যদি কোনো employer-এর পক্ষ থেকে contribution করেন, তাহলে আপনার employer-কে corporate CLA-তে স্বাক্ষর করতে হতে পারে।

## Developer Certificate of Origin (DCO)

DCO হলো CLA-এর তুলনায় সহজ একটি বিকল্প। এর মাধ্যমে আপনি নিশ্চিত করেন যে code জমা দেওয়ার অধিকার আপনার রয়েছে। প্রতিটি commit-এ একটি sign-off line যোগ করে এটি করতে হয়:

```bash
git commit -s -m "fix: handle empty username"
# যোগ করে: Signed-off-by: Your Name <you@example.com>
```

Pull Request-এর প্রতিটি commit পরীক্ষা করার জন্য একটি DCO bot কাজ করে। আপনি sign-off দিতে ভুলে গেলে নিচের command ব্যবহার করে ঠিক করতে পারেন:

```bash
git rebase --signoff upstream/main
git push --force-with-lease
```

Sign-off-এ দেওয়া নাম এবং email আপনার commit author-এর তথ্যের সঙ্গে মিলতে হবে।

## AI-এর সাহায্যে তৈরি Contribution

Maintainer-রা AI দিয়ে তৈরি নিম্নমানের Pull Request-এর সংখ্যা অনেক বেড়ে যেতে দেখেছেন। তাই এখন অনেক প্রজেক্টে AI ব্যবহারের বিষয়ে নির্দিষ্ট নিয়ম রয়েছে। একেক প্রজেক্টে এই নিয়ম একেক রকম হতে পারে:

- **সাধারণ নিয়ম মেনে ব্যবহার করা যাবে।** আপনার জমা দেওয়া প্রতিটি লাইনের দায়িত্ব আপনার। পাশাপাশি সেটি কীভাবে কাজ করে, তা ব্যাখ্যা করতে সক্ষম হতে হবে।
- **ব্যবহারের কথা জানিয়ে ব্যবহার করা যাবে।** PR description-এ কোন tool ব্যবহার করেছেন এবং কী কাজে ব্যবহার করেছেন, তা উল্লেখ করতে হবে। অথবা commit-এ `Assisted-by:`-এর মতো trailer যোগ করতে হতে পারে।
- **শুধু মানুষের লেখা communication গ্রহণযোগ্য।** Code লেখার ক্ষেত্রে AI সাহায্য করতে পারে, কিন্তু issue comment এবং PR description আপনাকেই লিখতে হবে।
- **সীমাবদ্ধ অথবা সম্পূর্ণ নিষিদ্ধ।** কিছু প্রজেক্টে AI দিয়ে তৈরি code বা documentation একেবারেই গ্রহণ করা হয় না। আবার কিছু প্রজেক্টে AI agent-কে Pull Request খুলতেও অনুমতি দেওয়া হয় না।

প্রজেক্টের নীতিমালা যাই হোক না কেন, নিচের নিয়মগুলো সব ক্ষেত্রেই প্রযোজ্য:

- আপনি যে পরিবর্তন জমা দিচ্ছেন, তার প্রতিটি অংশ বুঝতে হবে এবং প্রয়োজনে সেটির পক্ষে যুক্তি দিতে সক্ষম হতে হবে।
- নিজে যাচাই না করে কোনো tool-কে আপনার নামে Pull Request খুলতে বা comment করতে দেবেন না।
- কোনো প্রজেক্টে AI ব্যবহারের কথা জানানোর নিয়ম থাকলে তা ঠিকভাবে মেনে চলুন। যেখানে AI ব্যবহারের কথা জানানো বাধ্যতামূলক, সেখানে তা গোপন করলে প্রজেক্ট থেকে ban হওয়ার ঝুঁকি থাকে।

## Anti-spam এবং প্রথমবারের Contributor-দের জন্য Automation

Spam-এর কারণে কিছু প্রজেক্টে এমন workflow থাকে, যা স্বয়ংক্রিয়ভাবে Pull Request বন্ধ করে দেয় অথবা label যোগ করে। বাস্তব প্রজেক্টে দেখা যায়, এমন কিছু নিয়ম হলো:

- অল্প সময়ের মধ্যে অনেকগুলো সম্পর্কহীন repository-তে PR খোলা account-এর Pull Request বন্ধ করে দেওয়া।
- অন্য repository-তে সম্প্রতি প্রত্যাখ্যাত Pull Request জমা দেওয়া author-এর PR বন্ধ করে দেওয়া।
- AI tool-এর নামে তৈরি branch থেকে আসা PR বন্ধ করে দেওয়া (যেমন `claude/...` অথবা `codex/...`)।
- PR গ্রহণের আগে একটি linked issue অথবা `help wanted`-এর মতো issue label থাকা বাধ্যতামূলক করা।
- প্রতিটি checkbox পূরণ করে PR template জমা দেওয়া বাধ্যতামূলক করা।
- প্রথমবারের contributor-দের ক্ষেত্রে maintainer অনুমোদন না দেওয়া পর্যন্ত CI আটকে রাখা (এটি স্বাভাবিক এবং এতে চিন্তার কিছু নেই)।

কোন নিয়মগুলো আপনার ক্ষেত্রে প্রযোজ্য, তা জানতে `.github/workflows/` directory-তে `close-spam`, `first-interaction`, অথবা `pr-checks`-এর মতো নামের file খুঁজে দেখুন।

ব্যবহারিক পরামর্শ হলো, এক সপ্তাহে কয়েক ডজন repository-তে Pull Request না খুলে অল্প কয়েকটি প্রজেক্টে নিয়মিত ও মানসম্মত contribution করুন।

## আইনি ঘোষণা এবং লাইসেন্সিং

কিছু প্রজেক্টে Pull Request-এর সঙ্গে নির্দিষ্ট ঘোষণা যোগ করতে বলা হয়। যেমন, আপনি নিজে code লিখেছেন এবং সেটি প্রজেক্টের লাইসেন্সের শর্ত অনুযায়ী প্রকাশ করছেন।

শুধু সত্য এমন কথাই ঘোষণা করবেন। সাধারণত contribution জমা দেওয়ার মাধ্যমে আপনি সেটিকে প্রজেক্টের লাইসেন্সের অধীনে ব্যবহারের অনুমতি দেন। তাই সেই লাইসেন্সের শর্তগুলো আপনার (এবং প্রযোজ্য হলে আপনার employer-এর) কাছে গ্রহণযোগ্য কি না, তা যাচাই করে নিন।

## Checklist

- [ ] আমি contributing guide, PR template এবং AI policy বা agent instructions পড়েছি।
- [ ] আমার CLA অথবা DCO sign-off প্রয়োজন কি না, তা আমি জানি।
- [ ] প্রজেক্টের commit message এবং PR title লেখার নিয়ম আমি জানি।
- [ ] আমার PR স্বয়ংক্রিয়ভাবে বন্ধ হয়ে যেতে পারে কি না, তা জানতে `.github/workflows/` পরীক্ষা করেছি।
- [ ] AI-এর সাহায্য নিয়ে থাকলে সেটি কীভাবে এবং জানানো বাধ্যতামূলক কি না, তা আমি জানি।
