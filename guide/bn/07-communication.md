
# 7. মেইনটেইনারদের সঙ্গে যোগাযোগ

মেইনটেইনাররা সাধারণত স্বেচ্ছাসেবক অথবা ব্যস্ত প্রকৌশলী, যারা নিজেদের কাজের পাশাপাশি অন্যদের অবদানও পর্যালোচনা করেন। স্পষ্ট, সংক্ষিপ্ত এবং নির্দিষ্টভাবে যোগাযোগ করলে দ্রুত ও বন্ধুত্বপূর্ণ উত্তর পাওয়া যায়।

## একটি Issue নিজের নামে নেওয়া

কিছু প্রজেক্টে কাজ শুরু করার আগে মন্তব্য করতে হয়; আবার কিছু প্রজেক্টে সরাসরি "শুধু একটি PR খুলুন" বলা হয়। তাই প্রথমে Contributing Guide দেখে নিন। মন্তব্য করলে সেটি যেন কার্যকর হয়:

> আমি 4.2.1 সংস্করণে সমস্যাটি পুনরায় ঘটাতে পেরেছি: `tool --flag ""` কোনো error না দেখিয়ে অনির্দিষ্টকাল চলতে থাকে। `src/prompt.ts`-এর check খালি input প্রত্যাখ্যান করে, কিন্তু তার কারণ দেখায় না। আমি validation message দেখিয়ে আবার input নেওয়ার ব্যবস্থা করতে চাই এবং `prompt.test.ts`-এ একটি test যোগ করতে চাই। আমি কি কাজটি শুরু করতে পারি?

এটি "আমি কি এই কাজটি করতে পারি?" বলার চেয়ে ভালো। কারণ এতে বোঝা যায় যে আপনি সমস্যাটি বুঝেছেন। পাশাপাশি, সময় ব্যয় করার আগেই মেইনটেইনার আপনার পরিকল্পনা সংশোধন করতে পারেন।

একসঙ্গে একাধিক Issue নিজের নামে নেবেন না এবং যে Issue-তে এই সপ্তাহে কাজ শুরু করতে পারবেন না, সেটিও নিজের নামে নেবেন না।

## সাহায্য চাওয়া

কোনো সমস্যায় আটকে গেলে Issue-তে (অথবা প্রজেক্টের নিজস্ব chat থাকলে সেখানে) সাহায্য চান এবং নিচের বিষয়গুলো উল্লেখ করুন:

- আপনি কী করার চেষ্টা করছেন।
- আপনি কী কী চেষ্টা করেছেন।
- কী ঘটেছে, সঙ্গে সঠিক error message অথবা output।
- প্রয়োজন অনুযায়ী আপনার কাজের পরিবেশ (Operating System, language version এবং project version)।

যে code line সম্পর্কে জানতে চাইছেন, সেটির link দিন। উত্তর পাওয়ার অপেক্ষায় নিজের অনুসন্ধান চালিয়ে যান। উত্তর খুঁজে পেলে সেটি Issue-তে জানিয়ে দিন।

## Pull Request-এর বিবরণ লেখা

Reviewers অনেকগুলো Pull Request পর্যালোচনা করেন। তাই আপনার PR-এর বিবরণ এমনভাবে লিখুন, যাতে ৩০ সেকেন্ডের মধ্যে সেটি বোঝা যায়।

**ভালো উদাহরণ:**

> Fixes #1234.
>
> `login`-এ username খালি থাকলে বারবার input চাওয়া হচ্ছিল। কারণ `validateUsername` একটি error ফেরত দিলেও prompt loop সেটি উপেক্ষা করছিল। এখন loop আবার input চাওয়ার আগে validation message দেখায়।
>
> `prompt.test.ts`-এ একটি test যোগ করা হয়েছে, যা এই পরিবর্তন ছাড়া ব্যর্থ হয়। `npm test` এবং `npm run lint` সফলভাবে সম্পন্ন হয়েছে।

**এটি কেন ভালো:**

এতে Issue-এর link রয়েছে, কী ভুল ছিল এবং কেন ছিল তা বলা হয়েছে, কী পরিবর্তন করা হয়েছে তা বোঝানো হয়েছে এবং কীভাবে পরীক্ষা করা হয়েছে তাও উল্লেখ রয়েছে। অপ্রয়োজনীয় কথা নেই।

**যা এড়িয়ে চলবেন:**

- দীর্ঘ AI-তৈরি summary, পরিবর্তিত প্রতিটি file-এর তালিকা অথবা মাত্র দশ লাইনের পরিবর্তনের জন্য অতিরিক্ত heading।
- Marketing ভাষা ব্যবহার করা ("এই PR প্রজেক্টের উন্নতি উল্লেখযোগ্যভাবে বাড়িয়েছে...")।
- যাচাই না করা দাবি করা ("সব সম্পর্কিত সমস্যা সমাধান করে")।
- Template-এর placeholder text রেখে দেওয়া।

Reviewers-এর জানা দরকার এমন কিছু থাকলে সরাসরি বলুন:

> Custom registry-র ক্ষেত্রে খালি username অনুমোদিত হওয়া উচিত কি না, তা নিয়ে আমি নিশ্চিত ছিলাম না। তাই সেখানে আগের আচরণই বজায় রেখেছি।

## যোগাযোগের ধরন

- ভদ্র থাকুন এবং অন্যদের ভালো উদ্দেশ্য আছে বলে ধরে নিন, এমনকি কেউ সংক্ষিপ্তভাবে উত্তর দিলেও।
- Reviewers-দের সময় দেওয়ার জন্য একবার ধন্যবাদ জানান। প্রতিটি মন্তব্যের জন্য আলাদাভাবে ধন্যবাদ জানানোর প্রয়োজন নেই।
- বারবার মেইনটেইনারদের @mention করবেন না এবং আলোচনার সঙ্গে সম্পর্ক নেই এমন ব্যক্তিদের ping করবেন না।
- আমন্ত্রণ না জানানো হলে ব্যক্তিগত message-এর পরিবর্তে Issue অথবা Pull Request-এই আলোচনা চালিয়ে যান।
- নিজের ভাষায় লিখুন। মেইনটেইনাররা বুঝতে চান যে অবদানকারী নিজেই পরিবর্তনটি বুঝেছেন।

## পরবর্তী যোগাযোগ

প্রায় এক সপ্তাহ পরেও উত্তর না পেলে, একবার ভদ্রভাবে follow-up করতে পারেন:

> বিনীতভাবে মনে করিয়ে দিচ্ছি: সময় পেলে এটি review করার জন্য প্রস্তুত রয়েছে। প্রয়োজন হলে পরিবর্তন করতে আমি আগ্রহী।

প্রজেক্টে অবদানকারীদের জন্য chat channel থাকলে সেখানে একবার জিজ্ঞাসা করতে পারেন। এরপর অপেক্ষা করুন। কিছু প্রজেক্টে উত্তর পেতে স্বাভাবিকভাবেই বেশি সময় লাগে।

## যাচাই তালিকা

- [ ] আমার Issue claim comment (প্রয়োজন হলে) দেখায় যে আমি সমস্যাটি বুঝেছি।
- [ ] আমার PR description-এ কী ভুল ছিল, কী পরিবর্তন করেছি, কীভাবে পরীক্ষা করেছি এবং Issue-এর link রয়েছে।
- [ ] Template-এর placeholder text সরিয়ে দিয়েছি।
- [ ] আমার follow-up message-গুলো যথেষ্ট বিরতি দিয়ে এবং ভদ্রভাবে পাঠানো হয়েছে।
