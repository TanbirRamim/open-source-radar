# 3. একটি প্রজেক্ট বেছে নিন

কোন issue-তে কাজ করছেন, তার চেয়ে প্রজেক্টটি বেশি গুরুত্বপূর্ণ। একটি সক্রিয় ও অবদানকারীদের স্বাগত জানায় এমন প্রজেক্ট আপনার pull request কয়েক দিনের মধ্যেই review করতে পারে। অন্যদিকে, নিষ্ক্রিয় বা অতিরিক্ত কাজের চাপে থাকা প্রজেক্ট আপনার কাজ যত ভালোই হোক, সেটি হয়তো কখনো review করবে না।

## আপনি যে প্রজেক্ট ব্যবহার করেন, সেখান থেকে শুরু করুন

প্রথম অবদানের জন্য সবচেয়ে ভালো প্রজেক্ট হলো এমন কিছু, যা আপনি ইতিমধ্যেই ব্যবহার করেন: আপনার নিজের কোডে ব্যবহৃত কোনো library, প্রতিদিন ব্যবহার করা কোনো tool, অথবা আপনার পছন্দের কোনো app। আপনি জানেন সেটি কীভাবে কাজ করার কথা, নিজের পরিবর্তন বাস্তবে পরীক্ষা করতে পারবেন এবং ফলাফলটি আপনার কাছে গুরুত্বপূর্ণ হবে।

মনে কোনো প্রজেক্ট না এলে, আপনার জানা programming language অনুযায়ী [issue index](../../issues/README.md) দেখুন এবং লক্ষ্য করুন কোন প্রজেক্টগুলো বারবার সামনে আসছে।

## একটি সক্রিয় ও অবদানকারীদের স্বাগত জানায় এমন প্রজেক্টের লক্ষণ

Repository-এর পেজে নিচের বিষয়গুলো যাচাই করুন। এখানে পাঁচ মিনিট সময় দিলে কয়েক সপ্তাহ অপেক্ষা করার ঝামেলা এড়াতে পারেন।

| কী যাচাই করবেন | কোথায় দেখবেন | ভালো লক্ষণ |
| --- | --- | --- |
| সাম্প্রতিক কার্যকলাপ | Commits tab এবং "last commit"-এর তারিখ | গত কয়েক সপ্তাহে commit হয়েছে |
| বাইরের অবদানকারীদের merge হওয়া অবদান | **Pull requests → Closed**, `is:merged` filter ব্যবহার করে authors দেখুন | গত এক মাসে maintainer নন, এমন ব্যক্তিদের pull request merge হয়েছে |
| Review-এর গতি | বাইরের অবদানকারীদের সম্প্রতি merge হওয়া কয়েকটি PR খুলুন | কয়েক দিনের মধ্যে প্রথম উত্তর আসে, কয়েক মাস পরে নয় |
| Contributing guide | Root-এর `CONTRIBUTING.md`, `.github/` অথবা `docs/` | ফাইলটি আছে এবং setup ও testing-এর নির্দেশনা দেয় |
| নতুনদের জন্য label | Issues-এ `good first issue` অথবা `help wanted` filter ব্যবহার করুন | Label ব্যবহার করা হয় এবং চিহ্নিত issue-গুলোতে কাজ শুরু হয় |
| আলোচনার ধরন | কয়েকটি issue discussion পড়ুন | Maintainer-রা না বলার সময়ও ধৈর্যশীল ও স্পষ্ট থাকেন |
| Code of conduct | `CODE_OF_CONDUCT.md` | ফাইলটি আছে |
| CI | সাম্প্রতিক PR-এর checks | Pull request-এ স্বয়ংক্রিয়ভাবে test চালানো হয় |

যেকোনো repository-তে বাইরের অবদানকারীদের merge হওয়া PR খুঁজতে নিচের লিংকটি ব্যবহার করতে পারেন (`OWNER/REPO`-এর জায়গায় repository-এর নাম বসান):

```text
https://github.com/OWNER/REPO/pulls?q=is:pr+is:merged+-author:app/dependabot+sort:updated-desc
```

কারা PR জমা দিয়েছেন, তা দেখুন। যদি সব merge হওয়া PR একই দুজনের কাছ থেকে আসে, তাহলে প্রজেক্টটি বাইরের অবদানকে খুব বেশি অগ্রাধিকার নাও দিতে পারে।

## সতর্ক হওয়ার লক্ষণ

- **শত শত open pull request review ছাড়া পড়ে আছে।** আপনার PR-টিও সেই অপেক্ষার তালিকায় যুক্ত হবে।
- **Contributing guide-এ বলা আছে যে প্রজেক্টটি pull request গ্রহণ করছে না**, অথবা শুধু নির্দিষ্ট label-যুক্ত issue-তে অবদান গ্রহণ করে। কিছু জনপ্রিয় প্রজেক্ট এভাবেই কাজ করে। তাদের নিয়ম মেনে চলুন।
- **সাম্প্রতিক প্রতিটি issue-তে ইতিমধ্যেই একাধিক প্রতিদ্বন্দ্বী pull request রয়েছে।** জনপ্রিয় প্রজেক্টে bug report হওয়ার কয়েক ঘণ্টার মধ্যেই PR জমা পড়তে পারে। সেখানে অবদান রাখা সম্ভব, তবে কম প্রতিযোগিতাপূর্ণ কাজ বেছে নিন—যেমন documentation, tests, আগে থেকে নিশ্চিত হওয়া পুরোনো bug, অথবা ছোট কোনো প্রজেক্ট।
- **Maintainer-রা কম পরিশ্রমে তৈরি করা pull request জমা না দিতে বলছেন।** সেই discussion-গুলো পড়ুন; সেখানে কী করা উচিত নয়, তা স্পষ্টভাবে বোঝা যায়।
- **কয়েক মাস ধরে কোনো commit হয়নি।** প্রজেক্টটির কাজ হয়তো শেষ, অথবা এটি পরিত্যক্ত।

## বড় প্রজেক্ট নাকি ছোট প্রজেক্ট?

| | বড় ও বিখ্যাত প্রজেক্ট | ছোট কিন্তু সক্রিয় প্রজেক্ট |
| --- | --- | --- |
| সহজ issue-তে প্রতিযোগিতা | খুব বেশি | কম |
| Review-এর গতি | অনেক পরিবর্তনশীল; বাইরের অবদানকারীদের ক্ষেত্রে প্রায়ই ধীর | প্রায়ই দ্রুত এবং ব্যক্তিগতভাবে যোগাযোগ করা যায় |
| প্রক্রিয়া | আনুষ্ঠানিক: templates, CLAs এবং কঠোর CI | তুলনামূলকভাবে সহজ |
| Mentorship | কখনো কখনো সুসংগঠিত প্রোগ্রাম থাকে | Maintainer-এর সঙ্গে সরাসরি যোগাযোগ |
| প্রোফাইলে পরিচিতির প্রভাব | পরিচিত নামের কারণে শক্তিশালী | নিয়মিত অবদানকারী হলে শক্তিশালী |

একটি ভালো কৌশল হলো প্রথম এক বা দুটি অবদান এমন একটি ছোট ও সক্রিয় প্রজেক্টে রাখা, যেখানে দ্রুত feedback পাওয়া যায়। এরপর শেখা অভিজ্ঞতা বড় প্রজেক্টে কাজে লাগান।

## Checklist

- [ ] গত এক মাসে প্রজেক্টটিতে commit হয়েছে।
- [ ] সম্প্রতি বাইরের অবদানকারীদের pull request merge হয়েছে।
- [ ] Contributing guide আছে এবং আমি সেটি পড়েছি।
- [ ] আমি নিজের কম্পিউটারে প্রজেক্টটি build ও run করতে পারি (chapter 5-এ এ বিষয়ে বলা হয়েছে)।
