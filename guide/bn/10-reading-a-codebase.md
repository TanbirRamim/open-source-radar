# 10. একটি codebase পড়া

হাজার হাজার ফাইল থাকা একটি প্রজেক্ট খুলে কোথা থেকে শুরু করবেন তা বুঝতে না পারাটা প্রথম দিকের একটি সাধারণ বাধা। আপনার পুরো প্রজেক্ট বোঝার দরকার নেই—শুধু issue থেকে শুরু করে যে কোডটি পরিবর্তন করবেন, সেই পর্যন্ত পথটুকু বুঝলেই চলবে।

## কোথা থেকে দেখা শুরু করবেন

যখন একটি নতুন repository আপনার কম্পিউটারে নেবেন, তখন প্রতিটি ফাইল পড়ার চেষ্টা করবেন না। তার বদলে নিচের entry point-গুলো ব্যবহার করুন:

- **মূল documentation-গুলো পড়ুন:**
  - **`README.md`:** প্রজেক্টটি আসলে কী কাজ করে, এটি কীভাবে সাজানো হয়েছে এবং আপনার কম্পিউটারে কীভাবে অ্যাপটি সেট আপ ও রান করবেন, তা এখানে ব্যাখ্যা করা থাকে।
  - **`CONTRIBUTING.md`:** অবদানকারীদের জন্য প্রজেক্টের নিয়মগুলো এখানে লেখা থাকে—যার মধ্যে কোডের style নির্দেশিকা, কীভাবে pull request খুলতে হবে এবং মেইনটেইনাররা কীভাবে পরিবর্তন জমা দেওয়ার আশা করেন তা অন্তর্ভুক্ত থাকে।
- **Test-গুলো খুঁজে বের করুন এবং চালান:**
  - **Test কী?** Test হলো আলাদা কিছু কোড ফাইল, যা প্রতিটি ফিচারে হাতে ক্লিক করে দেখার প্রয়োজন ছাড়াই অ্যাপটি সঠিকভাবে কাজ করছে কি না তা স্বয়ংক্রিয়ভাবে যাচাই করার জন্য লেখা হয়।
  - **এগুলো কোথায় থাকে?** প্রজেক্টের root directory-তে আলাদা `tests/` বা `test/` ফোল্ডার খুঁজুন, অথবা source ফাইলগুলোর পাশেই `auth.test.js` বা `auth_spec.rb`-এর মতো নামের ফাইল আছে কি না দেখুন।
  - **কীভাবে চালাবেন:** সঠিক কমান্ডটি (`npm test`, `pytest`, বা `cargo test`-এর মতো) জানতে `README.md` অথবা `CONTRIBUTING.md` দেখুন। এগুলো চালালে নিশ্চিত হওয়া যায় যে আপনার সেটআপ ঠিকভাবে কাজ করছে।
- **Issue-তে থাকা error text বা UI string খুঁজুন:** আপনার issue-তে যদি কোনো নির্দিষ্ট error message বা button-এর label উল্লেখ থাকে, তাহলে কোডের ঠিক কোথায় সেই লেখাটি আছে তা খুঁজে বের করতে আপনার এডিটরের global search (`Ctrl+Shift+F` বা `Cmd+Shift+F`) ব্যবহার করুন।

## Git-এর ইতিহাস খোঁজা

যে ফাইলটি পরিবর্তন করতে হবে সেটি খুঁজে পাওয়ার পর, Git আপনাকে সেই ফাইলের ইতিহাস জানাতে পারে:

| কমান্ড | কাজ |
| --- | --- |
| `git log -p path/to/file` | একটি ফাইলে শুরু থেকে করা প্রতিটি পরিবর্তন এবং তার কারণ দেখুন |
| `git blame path/to/file` | প্রতিটি লাইন কে লিখেছেন এবং কোন commit-এ লিখেছেন তা দেখুন |

## Execution এবং ইতিহাস অনুসরণ করা

- **Entry point থেকে অনুসরণ করুন:** প্রোগ্রামের execution কোথা থেকে শুরু হয় তা খুঁজে বের করুন (যেমন `main()`, কোনো API route handler, বা মূল UI component) এবং সেখান থেকে function call-গুলো ধরে মূল logic পর্যন্ত যান।
- **সাম্প্রতিক merge হওয়া pull request-গুলো দেখুন:** Repository-র closed PR-গুলোর মধ্যে যেগুলো একই অংশে পরিবর্তন করেছে, সেগুলো খুঁজে দেখুন। মেইনটেইনাররা পরিবর্তনগুলো কীভাবে format ও test করা দেখতে চান, তার একটি স্পষ্ট ধারণা এগুলো থেকে পাওয়া যায়।
