# Glossary

| Term | Meaning |
| --- | --- |
| **Assignee** | The person responsible for an issue. An assigned issue is usually taken. |
| **Branch** | An independent line of commits. You make each change on its own branch. |
| **CI (continuous integration)** | Automated checks (tests, linters, builds) that run on every pull request. |
| **CLA (Contributor License Agreement)** | A legal agreement some projects require before accepting contributions. |
| **Clone** | A local copy of a repository on your computer. |
| **Code owner** | A person or team automatically asked to review changes to certain files (`CODEOWNERS`). |
| **Commit** | A saved snapshot of changes, with a message describing them. |
| **Conventional Commits** | A commit message format like `fix(parser): handle empty input`. |
| **DCO (Developer Certificate of Origin)** | A statement you make by adding `Signed-off-by:` to commits (`git commit -s`). |
| **Default branch** | The main branch of a repository, usually `main` or `master`, sometimes `develop`. |
| **Draft pull request** | A pull request marked as not ready for review yet. |
| **Fork** | Your own copy of someone else's repository on GitHub. |
| **Force push** | Replacing a remote branch's history. Use `git push --force-with-lease` on your own branches only. |
| **Issue** | A bug report, feature request or task in a project's tracker. |
| **Linked pull request** | A pull request connected to an issue, often with `Fixes #123`. |
| **Linter** | A tool that checks code for style problems and likely bugs. |
| **Maintainer** | Someone with permission to review and merge contributions. |
| **Merge conflict** | When your branch and the target branch changed the same lines differently. |
| **Monorepo** | One repository containing many packages. Usually you build and test only the package you change. |
| **Pull request (PR)** | A request to merge your branch into another repository's branch. GitLab calls it a merge request. |
| **Rebase** | Replaying your commits on top of newer commits, to update a branch. |
| **Regression** | A bug where something that used to work stopped working. |
| **Repository (repo)** | A project's files and full history. |
| **Reproduction (repro)** | Minimal steps or code that make a bug happen reliably. |
| **Review** | Comments and approval (or change requests) from maintainers on a pull request. |
| **Squash** | Combining several commits into one, often done when merging. |
| **Stale** | An issue or pull request with no activity for a long time; bots may close it. |
| **Triage** | Sorting new issues: reproducing, labeling, finding duplicates. |
| **Upstream** | The original repository you forked from. |
