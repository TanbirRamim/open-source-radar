# 9. आगे बढ़ते रहें

एक merged Pull Request एक शानदार शुरुआत है। Skills और reputation असल में वहीं बनते हैं जब आप किसी एक प्रोजेक्ट में नियमित contributor बन जाते हैं।

## चौड़ाई नहीं, गहराई

अपने पहले योगदान के बाद उसी प्रोजेक्ट में अगला योगदान दें। दूसरा Pull Request काफ़ी तेज़ बनता है: setup, tests, conventions और लोग — सब आपको पहले से पता है। पाँचवें तक maintainers आपका नाम पहचानने लगते हैं और आपके PR जल्दी review होते हैं।

नियमित contributor बनने के संकेत:

- Maintainers अपने क्षेत्र के issues पर आपको mention करते हैं।
- आप नए issues को triage कर सकते हैं: उन्हें reproduce करना, label करना और duplicates बताना।
- दूसरे contributors आपसे सवाल पूछते हैं।

## अपने योगदान बढ़ाते जाएँ

एक स्वाभाविक क्रम:

1. साफ़-सुथरे scope वाले **bug fixes और docs**।
2. ऐसे हिस्सों के लिए **tests**, जहाँ tests नहीं हैं, और नए issues का **triage**।
3. **छोटे features**, जिन पर maintainers ने issue में पहले ही सहमति दे दी हो।
4. दूसरों के Pull Requests के **reviews**। पहले maintainers से पूछ लें कि बाहर से review का स्वागत है या नहीं।
5. **बड़ा काम**: design proposals, refactors, releases। ये लिखने से पहले discuss करें।

## Contributor पद देने या mentor करने वाले programs

ये समय के साथ बदलते रहते हैं, इसलिए तारीख़ और eligibility हर program की site पर जाकर खुद देखें:

- [Google Summer of Code](https://summerofcode.withgoogle.com): open source organizations के साथ paid, mentored गर्मी के projects.
- [Outreachy](https://www.outreachy.org): tech में कम दिखने वाले समूहों के लोगों के लिए paid internships.
- [LFX Mentorship](https://mentorship.lfx.linuxfoundation.org): Linux Foundation और CNCF projects में mentored projects.
- [GitHub Sponsors](https://github.com/sponsors): कुछ maintainers और contributors, जब उनकी पहचान बन जाती है, sponsorship पाते हैं।
- कई foundations और companies अपने programs या bounties चलाती हैं; projects के README में उनके links मिल जाते हैं।

## अपना काम दिखाना

- अपने सबसे अच्छे योगदान अपने GitHub profile पर pin करें, या profile README में सूची बनाएँ।
- Merged Pull Requests को profile की जगह सीधे अपने CV में link करें: "login prompt में एक infinite loop ठीक किया (owner/project#1234)"।
- जो सीखा उस पर लिखें। किसी असली प्रोजेक्ट के असली issue के debugging पर एक छोटी post पढ़ने में दिलचस्प होती है।

## अपना प्रोजेक्ट शुरू करना

जब आप खुद कुछ publish करें, तो जो बातें आपको दूसरे projects में स्वागत करने लगीं, वे उलटकर आप पर लागू होती हैं: setup steps वाला README, एक `CONTRIBUTING.md`, license, newcomers के लिए issue labels, और पहले दिखने वालों को तेज़ और प्यार भरे जवाब।

## Burnout से बचें

- जब आपके लिए sustainable हो तभी योगदान दें। Open source कोई नौकरी नहीं है, जब तक कोई इसके पैसे न दे रहा हो।
- किसी issue से खुद को unassign करना बिलकुल ठीक है, अगर आप उसे पूरा नहीं कर सकते। Issue पर बता दें।
- ब्रेक लेना बिलकुल ठीक है।

## चेकलिस्ट

- [ ] मैंने नियमित contributor बनने के लिए एक प्रोजेक्ट चुना।
- [ ] मेरे merged योगदानों की links वाली सूची मेरे पास है।
- [ ] मुझे पता है कि कौन-कौन से mentorship या paid programs मेरे लिए उपलब्ध हो सकते हैं।
