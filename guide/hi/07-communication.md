# 7. Maintainers से बातचीत करना

जब आप ओपन सोर्स में काम करते हैं, तो आपका अधिकांश समय maintainers और अन्य contributors के साथ बातचीत करने में बीतता है। यह कोड लिखने जितना ही महत्वपूर्ण है।

अच्छी बातचीत से maintainers का काम आसान हो जाता है और आपकी PR जल्दी merge हो जाती है। खराब बातचीत से लोग थका हुआ महसूस करते हैं और कभी-कभी PR बंद भी हो सकती है।

---

## काम शुरू करने से पहले issue को claim करें

जब आपको कोई ऐसा issue मिल जाए जिसे आप ठीक करना चाहते हैं, तो काम शुरू करने से पहले यह स्पष्ट कर दें कि आप उस पर काम कर रहे हैं।

- **देखें कि क्या वह किसी को assigned है:** अगर किसी ने पहले ही comment कर दिया है कि वे इस पर काम कर रहे हैं, या PR खुली है, तो दूसरा issue देखें।
- **अपनी रुचि बताएं:** issue पर एक छोटा comment छोड़ें।

> **अच्छा उदाहरण:**
> "नमस्ते, यह issue बहुत अच्छा लग रहा है। क्या मैं इस पर काम शुरू कर सकता हूँ?"

> **बुरा उदाहरण:**
> बिना कुछ कहे सीधे PR भेज देना, जबकि कोई और पहले से उस पर काम कर रहा था।

---

## सवाल पूछने के तरीके

जब आप किसी project में फंस जाते हैं, तो सवाल पूछना सामान्य बात है। लेकिन सवाल ऐसे पूछें कि सामने वाले को आपकी मदद करने में आसानी हो।

1. **बताएं कि आपने क्या कोशिश की है:** कभी न कहें "यह काम नहीं कर रहा है"। इसके बजाय बताएं "मैंने X किया, Y की उम्मीद थी, लेकिन Z हुआ"।
2. **Minimal reproducible example दें:** जितना हो सके उतना छोटा code snippet दें जो समस्या को दिखाता हो।
3. **धैर्य रखें:** maintainers अपने खाली समय में या किसी company के लिए काम करते हैं। जवाब मिलने में कुछ दिन लग सकते हैं।

---

## अच्छी PR descriptions लिखना

जब आप Pull Request खोलें, तो description में साफ-साफ बताएं कि आपकी PR क्या करती है।

- **समस्या क्या थी:** एक वाक्य में बताएं।
- **आपने क्या बदला:** समाधान का संक्षिप्त विवरण दें।
- **आपने इसे कैसे जांचा:** बताएं कि आपने किन tests या steps से इसे local रूप से परखा है।

---

## लहजा

- विनम्र रहें और अच्छे इरादे मानकर चलें, तब भी जब कोई छोटा या रूखा जवाब दे।
- Reviewers को उनके समय के लिए एक बार धन्यवाद दें। हर comment पर धन्यवाद कहने की ज़रूरत नहीं है।
- Maintainers को बार-बार @-mention न करें, और जो लोग इसमें शामिल नहीं हैं उन्हें ping न करें।
- बातचीत issue या pull request पर ही रखें, private messages में नहीं, जब तक आपको बुलाया न जाए।
- अपने शब्दों में लिखें। Maintainers जानना चाहते हैं कि बदलाव को एक इंसान समझता है।

## Follow up करना

अगर लगभग एक हफ्ते तक कोई जवाब न आए, तो एक विनम्र follow-up ठीक है:

> Friendly ping: this is ready for review whenever someone has time. Happy to make changes.

अगर project में contributors के लिए कोई chat channel है, तो वहाँ एक बार पूछना भी ठीक है। उसके बाद रुक जाएँ: कुछ projects बस धीमे होते हैं।
