# 10. कोडबेस को पढ़ना और समझना

शुरुआत में अक्सर सबसे बड़ी मुश्किल यह होती है कि आप किसी ऐसे प्रोजेक्ट को खोलते हैं जिसमें हज़ारों फ़ाइलें होती हैं, और आपको समझ नहीं आता कि शुरुआत कहाँ से करें। आपको पूरे कोडबेस को समझने की ज़रूरत नहीं है। आपको केवल उस रास्ते को समझना है जो issue से शुरू होकर उस कोड तक जाता है जिसे आप बदलने वाले हैं।

## कहाँ से देखना शुरू करें

जब आप किसी नई repository को अपने कंप्यूटर पर लाते हैं, तो हर फ़ाइल को पढ़ने की कोशिश न करें। इसके बजाय, इन जगहों से शुरुआत करें:

- **बुनियादी दस्तावेज़ पढ़ें:**
  - **`README.md`:** यह बताती है कि प्रोजेक्ट वास्तव में क्या करता है, इसकी संरचना कैसी है और अपने कंप्यूटर पर ऐप को कैसे सेट अप और रन करना है।
  - **`CONTRIBUTING.md`:** यह contributors के लिए प्रोजेक्ट के नियम बताती है। इसमें code style के दिशा-निर्देश, Pull Request खोलने का तरीका और maintainers आपसे बदलाव किस तरह जमा करने की अपेक्षा करते हैं, जैसी बातें शामिल होती हैं।

- **Tests खोजें और चलाएँ:**
  - **Tests क्या होते हैं?** Tests कोड की अलग-अलग फ़ाइलें होती हैं, जो अपने-आप जाँचती हैं कि ऐप सही तरीके से काम कर रहा है या नहीं। इनके लिए आपको हर feature को खुद क्लिक करके जाँचने की ज़रूरत नहीं पड़ती।
  - **ये कहाँ मिलते हैं?** Repository के मुख्य फ़ोल्डर में `tests/` या `test/` नाम का फ़ोल्डर खोजें। आप source files के पास `auth.test.js` या `auth_spec.rb` जैसे नामों वाली फ़ाइलें भी देख सकते हैं।
  - **इन्हें कैसे चलाएँ?** सही command जानने के लिए `README.md` या `CONTRIBUTING.md` देखें। उदाहरण के लिए, `npm test`, `pytest` या `cargo test`। Tests चलाने से यह पुष्टि करने में मदद मिलती है कि आपका setup सही काम कर रहा है।

- **Issue में दिए गए error message या UI text को खोजें:** अगर issue में कोई खास error message या button का नाम दिया गया है, तो उसे खोजने के लिए अपने editor का global search इस्तेमाल करें (`Ctrl+Shift+F` या `Cmd+Shift+F`)। इससे आपको पता चल सकता है कि वह text कोड में कहाँ लिखा गया है।

## Git की मदद से पुराने बदलावों को समझना

जब आपको वह फ़ाइल मिल जाए जिसमें बदलाव करना है, तो Git की मदद से आप उसके इतिहास को समझ सकते हैं:

| Command | यह क्या करता है |
| --- | --- |
| `git log -p path/to/file` | फ़ाइल में समय के साथ हुए बदलावों और उनके पीछे के कारणों को देखता है |
| `git blame path/to/file` | दिखाता है कि हर लाइन किसने लिखी थी और वह किस commit में जोड़ी गई थी |

## कोड के execution flow और इतिहास को समझना

- **Entry point से शुरुआत करें:** पता लगाएँ कि कोड का execution कहाँ से शुरू होता है। यह `main()`, कोई API route handler या मुख्य UI component हो सकता है। इसके बाद function calls को follow करते हुए उस logic तक पहुँचें जिसे आप समझना चाहते हैं।
- **हाल ही में merge हुए Pull Requests देखें:** Repository में उन पुराने, बंद हो चुके PRs को खोजें जिनमें उसी हिस्से में बदलाव किए गए थे। उनसे आपको समझने में मदद मिलेगी कि maintainers किस तरह के code formatting और tests की अपेक्षा करते हैं।

## चेकलिस्ट

- [ ] मैंने यह समझने के लिए `README.md` पढ़ी कि प्रोजेक्ट क्या करता है और इसे कैसे चलाना है।
- [ ] मैंने प्रोजेक्ट के नियमों और code style को समझने के लिए `CONTRIBUTING.md` पढ़ी।
- [ ] मैंने test suite खोजी, उसे चलाया और पुष्टि की कि सभी tests मेरे कंप्यूटर पर सफलतापूर्वक पास हुए।
- [ ] मैंने issue में दिए गए error message या UI text को खोजकर उससे जुड़ी फ़ाइलें ढूँढ़ीं।
- [ ] मैंने प्रोजेक्ट के conventions को समझने के लिए हाल ही में merge हुए PRs या Git history को देखा।
