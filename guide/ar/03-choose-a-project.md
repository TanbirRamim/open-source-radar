# 3. اختيار مشروع

المشروع أهم من المشكلة نفسها. المشروع النشط الذي يرحّب بالمساهمين سيراجع الـ Pull Request الخاص بك خلال أيام. أما المشروع الخامل أو المثقل بالأعمال فقد لا ينظر إليه أبدًا، مهما كان جيدًا.

## ابدأ مما تستخدمه

أفضل مشروع أول هو مشروع تستخدمه بالفعل: مكتبة في شيفرتك، أو أداة تشغّلها يوميًا، أو تطبيق يعجبك. فأنت تفهم ما يُفترض أن يفعله، وتستطيع اختبار تغييرك على أرض الواقع، وتهتم بالنتيجة.

إذا لم يخطر ببالك أي مشروع، فتصفّح [فهرس المشكلات](../../issues/README.md) حسب اللغة البرمجية التي تتقنها أكثر، ولاحظ المشاريع التي يتكرر ظهورها.

## علامات المشروع السليم الذي يرحّب بالمساهمين

تحقق من هذه الأمور في صفحة المستودع. خمس دقائق هنا توفر عليك أسابيع من الانتظار.

| ما تتحقق منه | أين تجده | العلامة الجيدة |
| --- | --- | --- |
| النشاط الأخير | تبويب Commits، تاريخ "last commit" | عمليات إيداع خلال الأسابيع القليلة الماضية |
| مساهمات خارجية مدمجة | **Pull requests → Closed**، صفِّ باستخدام `is:merged` وانظر إلى أصحابها | دُمجت خلال الشهر الماضي طلبات Pull Request من أشخاص ليسوا من المشرفين |
| سرعة المراجعة | افتح بعض طلبات PR التي دُمجت مؤخرًا لمساهمين من خارج الفريق | الرد الأول خلال أيام، لا أشهر |
| دليل المساهمة | `CONTRIBUTING.md` في المجلد الرئيسي أو `.github/` أو `docs/` | موجود ويشرح الإعداد والاختبار |
| تصنيفات المبتدئين | تبويب Issues، صفِّ حسب `good first issue` أو `help wanted` | التصنيفات مستخدمة، والمشكلات المصنفة بها تجد من يتولاها |
| أسلوب التعامل | اقرأ بعض النقاشات في المشكلات | المشرفون صبورون ومحددون، حتى عند الرفض |
| قواعد السلوك | `CODE_OF_CONDUCT.md` | موجودة |
| التكامل المستمر (CI) | الفحوصات في طلبات PR الأخيرة | تعمل الاختبارات تلقائيًا على كل Pull Request |

إليك بحثًا سريعًا يعرض طلبات PR المدمجة من مساهمين خارجيين في أي مستودع (استبدل `OWNER/REPO`):

```text
https://github.com/OWNER/REPO/pulls?q=is:pr+is:merged+-author:app/dependabot+sort:updated-desc
```

انظر إلى أصحاب الطلبات: إذا كانت كل طلبات PR المدمجة من الشخصين نفسيهما، فقد لا تكون المساهمات الخارجية من أولويات المشروع.

## علامات التحذير

- **مئات من طلبات Pull Request المفتوحة دون مراجعة.** سينضم طلبك إلى الطابور.
- **دليل مساهمة ينص على أن المشروع لا يقبل طلبات Pull Request**، أو لا يقبلها إلا للمشكلات التي تحمل تصنيفًا معينًا. بعض المشاريع المشهورة تعمل بهذه الطريقة. احترم ذلك.
- **كل مشكلة حديثة عليها عدة طلبات PR متنافسة.** كثيرًا ما تتلقى المشاريع المشهورة طلبات PR عابرة خلال ساعات من الإبلاغ عن خطأ. لا يزال بإمكانك المساهمة فيها، لكن اختر عملًا أقل تنافسًا (التوثيق، أو الاختبارات، أو الأخطاء القديمة المؤكدة) أو مشروعًا أصغر.
- **مشرفون يطلبون من الناس التوقف عن فتح طلبات Pull Request قليلة الجهد.** اقرأ تلك النقاشات: فهي تخبرك بالضبط بما يجب ألا تفعله.
- **لا توجد عمليات إيداع منذ أشهر.** قد يكون المشروع مكتملًا أو مهجورًا.

## مشروع كبير أم صغير؟

| | مشروع كبير ومشهور | مشروع أصغر ونشط |
| --- | --- | --- |
| المنافسة على المشكلات السهلة | عالية جدًا | منخفضة |
| سرعة المراجعة | تتفاوت كثيرًا، وغالبًا ما تكون بطيئة مع المساهمين الخارجيين | غالبًا سريعة وشخصية |
| الإجراءات | رسمية: قوالب، واتفاقيات ترخيص المساهم (CLA)، وفحوصات CI صارمة | أخف |
| الإرشاد | توجد أحيانًا برامج منظمة | تواصل مباشر مع المشرف |
| أثره على ملفك الشخصي | اسم معروف يلفت الانتباه | أثر قوي إذا أصبحت مساهمًا منتظمًا |

من الاستراتيجيات الجيدة: قدّم أول مساهمة أو مساهمتين في مشروع أصغر ونشط تحصل فيه على ملاحظات سريعة، ثم انقل ما تعلمته إلى مشاريع أكبر.

## قائمة التحقق

- [ ] شهد المشروع عمليات إيداع خلال الشهر الماضي.
- [ ] دمج المشروع مؤخرًا طلبات Pull Request من مساهمين خارجيين.
- [ ] لديه دليل مساهمة، وقد قرأته.
- [ ] أستطيع بناءه وتشغيله على جهازي (يشرح الفصل 5 ذلك).
